Wildcard Mask Reference

A wildcard mask is the inverse of a subnet mask: a 0 bit means "this bit must match", a 1 bit means "don't care". Subtract each octet of the subnet mask from 255 to get it.

Contiguous wildcards. Every wildcard above is a run of 1s at the bottom and nothing else — in a single octet that is one of 1, 3, 7, 15, 31, 63, 127, 255. Each is one less than the block size, and they are the only values that describe a single run of consecutive addresses.

These are also the only wildcards a subnet mask can be inverted into, which is why they are very nearly all you will ever meet in a real configuration. A wildcard with a gap in it — 0.0.0.254, or 0.0.0.225 — is legal, and IOS will do exactly what it says, but it matches a scattered set of addresses rather than a block. Those turn up on Hard.

Two shorthands mean exactly the same thing as a wildcard: host 192.168.30.3 is 192.168.30.3 0.0.0.0, and any is 0.0.0.0 255.255.255.255.

Binary Compare

Scratch space for working a wildcard out by hand. Nothing here is graded or checked — it only writes what you type in binary, stacked so the bit columns line up.

Read it one column at a time. Where Wildcard has a 1, nothing in that column is checked — ACE and Test are free to differ there and it makes no difference. Where Wildcard has a 0, that column is checked: ACE and Test must carry the same bit. The address matches only if every 0 column agrees — one disagreement in a single one of them rules it out, however many other columns line up.

Why the placement rule differs. A standard ACL can only see where a packet came from, so filtering it early would block that source from reaching everything, not just the one network you meant to protect. An extended ACL knows the destination too, so it can be applied early and drop unwanted traffic before it crosses the network.

Order matters. ACEs are checked top to bottom and the first match wins — nothing after it is considered. A broad permit above a specific deny makes that deny unreachable.

There is always an implicit deny any at the end of every ACL, so anything not explicitly permitted is dropped. Adding an explicit deny any changes nothing functionally, but it shows up in show access-lists with a match counter, which is genuinely useful when troubleshooting.

An ACL applied to an interface filters traffic passing through the router. An ACL applied to the vty lines with access-class filters traffic to the router itself — who is allowed to log in.

Extended ACLs

An extended entry names a protocol, a source and a destination, and for tcp/udp optionally a port. Because it can be that specific, it goes close to the source. Lists 100–199 are extended; a named one uses ip access-list extended. End it with permit ip any any or the implicit deny drops everything else.

CommandModeWhat it does
access-list 100 deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255configAny IP traffic from one network to another

SSH

SSH needs a domain name (the keys are named after it), RSA keys — at least 768 bits for version 2 — a local user, and vty lines that use login local and accept transport input ssh. Test it from a PC once the device is reachable.

The same lab in IPv6

Three things change and nothing else does. There are no wildcards — a network is written with its prefix length, 2001:db8:acad:10::/64. There are no numbered lists — every IPv6 ACL is named. And every entry names a source and a destination, because IPv6 has no "standard" list; a policy that only cares about the source says any for the destination.

NAT Reference

NAT rewrites the source address of a packet crossing from an ip nat inside interface to an ip nat outside one, and rewrites the destination of the reply coming back. It exists because the ISP has no route to your private addresses — a packet from 192.168.1.20 gets to the Internet fine; it is the reply that has nowhere to go.

ICMP has no ports, so a translation shows the ping's identifier in the port position. SSH is tcp to well-known port 22. The type buttons above pick which NAT the round is built for; there is no IPv6 in this lab, because IPv6 was designed so that every host has a public address and NAT is not needed.
