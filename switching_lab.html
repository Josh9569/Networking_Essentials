VLAN / Trunk Reference
  • 1
    An access port belongs to exactly one VLAN and connects end devices (PCs). Frames on it are untagged — the switch tracks the VLAN internally.
    switchport mode access · switchport access vlan 10
  • 2
    A trunk port carries multiple VLANs between switches using 802.1Q tags. Both ends of the link must be trunks or traffic will not pass correctly.
    switchport mode trunk
  • 3
    Two PCs can only communicate at Layer 2 if they are in the same VLAN and every switch-to-switch link on the path carries that VLAN.
  • 4
    EtherChannel bundles multiple physical links into one logical link (more bandwidth, no STP blocking between them). Every member port on a switch must share the same channel-group number and the same trunk settings as its port-channel interface, or it is suspended. The two ends must agree on a mode: LACP (active with active or passive), PAgP (desirable with desirable or auto), or on at both ends. passive+passive and auto+auto never bundle.
    channel-group 1 mode active · interface port-channel 1
  • 5
    A trunk carries every VLAN until you restrict its allowed list. A VLAN missing from the list at either end does not cross the link. Use add to extend the list without retyping it — a bare list replaces what was there.
    switchport trunk allowed vlan 10,20 · switchport trunk allowed vlan add 99
  • 6
    Port security limits which MAC addresses an access port accepts. Addresses are learned from traffic (or typed in); sticky writes learned ones into the running config. A frame from one address too many is a violation: shutdown (the default) err-disables the port, restrict drops and counts it, protect drops it silently. An err-disabled port only recovers with shutdown then no shutdown.
    switchport port-security · switchport port-security mac-address sticky
STP Rules
  • 1
    Root bridge election: the switch with the lowest bridge ID wins. Bridge ID = priority + MAC address. Compare priority first; if tied, the lowest MAC wins.
  • 2
    Every non-root switch picks one root port — the port with the lowest total path cost to the root (FastEthernet link = cost 19).
  • 3
    Each link segment gets one designated port — the end whose switch has the lower path cost to the root; ties are broken by lower bridge ID. All root-bridge ports are designated.
  • 4
    Any port that is neither a root port nor a designated port becomes blocking — this breaks the loop. In a triangle of switches exactly one port blocks: on the redundant link, the end belonging to the switch with the higher bridge ID.
  • 5
    Priorities can also be set with keywords: root primary configures priority 24576 and root secondary configures 28672, both lower (better) than the default 32768. Lower always wins the election.
    spanning-tree vlan 1 root primary
Command Reference

The CLI accepts Cisco IOS syntax with standard abbreviations (e.g. conf t, int fa0/1, sw mo ac). As on a real switch, each command only works in its own mode: show at # (or do show in configuration mode), switchport on a switch port, ip address on an SVI. A wrong-mode command is refused with a hint saying where it belongs. Press Tab to auto-complete keywords and use the ↑ / ↓ arrow keys for command history.
