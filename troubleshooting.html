Where to Look

Work from Layer 2 up: a check higher up the stack only means something once everything under it is right. Reproduce the ticket first, then ping the PC's own gateway — the last thing that answers tells you which device to open.

SymptomCheck, in order
A PC cannot ping its own gatewayVLANs and access ports → port security → trunks → EtherChannel → router subinterfaces → the PC's own settings
Nothing reaches a switch's management addressTrunks → the switch's VLAN SVI → its default gateway
The sites cannot reach each other over IPv4Serial link and PPP → router addressing → OSPF neighbours and networks → IPv4 ACLs
Only IPv6 is brokenIPv6 addresses and link-locals → ipv6 unicast-routing → OSPFv3 per interface → IPv6 ACLs
The Internet (5.5.5.5) is unreachableR1's default routes → default-information originate → ISP's routes back → NAT
SSH failsCan the PC ping the router? Then the SSH server: domain name, RSA keys, a local user, login local and transport input ssh

An exam report wants the root cause and device, the show commands that proved it, and the fix. show running-config does not count as proof — use it to read configuration, then prove the fault with a targeted show command.
